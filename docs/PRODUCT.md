# 캡처함: 제품 정의

## 한 문장

스크린샷을 앨범에 쌓는 대신, 다시 찾고 제때 쓰는 카드로 바꾼다.

## 핵심 고객과 사용 상황

업무 특화가 아닌 일반 소비자용이다. 쿠폰, 예약, 사고 싶은 상품, 방문할 장소를 캡처해 놓고 잊거나 다시 찾기 어려운 사용자를 대상으로 한다. 광범위한 메모 앱보다 **한 장 가져오기 → 필요한 정보 확인 → 행동하기**에 집중한다.

## 가장 먼저 검증할 사용자 경험

갤러리에서 쿠폰을 공유한다. 원본과 함께 제목·기한이 제안된다. 사용자가 날짜를 확인하고 `3일 전` 알림을 선택한다. 저장 후 나중에 검색하거나 `다가오는` 탭에서 찾고, 사용 후 완료 처리한다.

다른 흐름은 상품 가격 기록, 행사 캘린더 등록, 장소 이름 검색이다. 자동 분류를 잘못했을 때 손쉽게 고치는 것이 분류 정확도만큼 중요하다.

## 화면

보관함: 검색, 분류, 스크린샷 중심 그리드, 사용 완료 필터.
다가오는: 만료·예정 날짜 순 정렬, 확인이 필요한 날짜 표시.
상세: 원본, 제목, 분류, 날짜 확인, 알림, 링크·장소·원문 수정, 복사·공유·캘린더.
설정: 개인정보 설명, 원본 포함 백업·복원, 예시 관리, 한계 안내.

## 첫 버전에서 제외

전체 갤러리 자동 감시, 계좌번호 자동 전송, 위치 추적, 실시간 최저가, 지도 API, 자동 결제, 서버형 LLM, 로그인과 동기화, iOS. API 비용이나 서비스 운영을 늘리기 전에 핵심 사용 흐름을 검증한다.

## 차별화 가설

차별화가 검증됐거나 경쟁자가 없다는 뜻은 아니다. 한국어 쿠폰의 기한 확인과 사용 완료 흐름, 서버 전송 없는 처리, 간단한 단일 화면 편집을 제품 가설로 삼는다. 실제 스크린샷 인식률과 반복 사용 데이터를 확보하기 전에는 경쟁 우위·매출을 단정하지 않는다.

## 수익화 실험안 — 구현하지 않음

베타 기간에는 모든 핵심 기능을 무료로 제공한다. 이후 기본 보관·검색은 유지하고, 폴더·맞춤 정리 규칙·내보내기 편의성 등을 일회성 구매에 묶는 안을 시험한다. 예시 가격 9,900원 / 14,900원은 검증 전 가설이며 실제 상품 가격이 아니다. 서버 비용이 생기지 않는 기능에 무제한 AI 구독을 억지로 붙이지 않는다.

암호화 동기화가 도입될 때만 별도 구독의 필요성을 검토한다. 구독과 평생 이용권을 동시에 약속해 장기 서버 비용을 떠안지 않는다.

## 베타 검증 계획

쿠폰·예약·상품·장소·일반 글 각각 20장 이상의 사용 허락된 이미지로 테스트한다. 동일 이미지를 단순 중복 집계하지 않는다. 제목·분류·기한의 정답을 사람이 먼저 작성하고, 정확도와 사용자의 수정 빈도를 측정한다. 특히 `날짜가 없는데 만들어낸 경우`와 `기한의 시작/끝을 바꾼 경우`를 따로 기록한다.

초기 사용자 10~20명에게 기능을 설명하기 전에 한 장 가져오게 하고, 완료 여부·멈춘 지점·재검색 여부를 관찰한다. 가입자 수보다 다음 주에도 직접 가져와서 다시 사용했는지를 본다. 숫자는 실험 설계 예시일 뿐 성공 보장이나 시장 통계가 아니다.

## 출시 게이트

실제 날짜가 잘못 제안돼도 확인 없이 알림이 설정되지 않아야 한다. 삭제·복원 실패가 자료를 잃게 하면 출시하지 않는다. 대상 기기에서 알림 거부·저장 공간 부족·앱 재실행·폰트 확대를 확인한다. 원본이 서버로 전송되지 않는다는 설명은 최종 APK 권한과 네트워크 검사로 확인한다. 런처 아이콘과 고정 배포 서명은 정식 출시 작업에 포함한다.
